1. Introduction						*opencode-nvim-intro*

opencode-nvim is a floating panel for talking to OpenCode V2 (`opencode2`)
from inside Neovim. The conversation shows up in a float anchored to the bottom
right corner that does *not* steal focus: you keep seeing and editing your code
while the answer streams in.

The plugin talks straight to the OpenCode HTTP service (the same background
service the TUI uses), so sessions are shared with `opencode2` and the server is
already warm when you open Neovim.

Features:
  - Streaming of text, reasoning and tool calls in the panel.
  - Edit approval with the diff inside the editor, without leaving Neovim.
  - Buffers changed by the AI reload automatically, keeping the cursor.
  - Editor context through `@this`, `@buffer`, `@buffers`, `@diagnostics` and
    `@diff`.
  - No required dependencies (only what ships with Neovim).

==============================================================================
2. Requirements					*opencode-nvim-requirements*

  - Neovim 0.11 or newer (uses `vim.uv`, `vim.json`, `vim.base64`, `vim.fs`).
  - OpenCode V2 installed as `opencode2` in `PATH`.
  - The OpenCode background service (`opencode2 serve` / the shared service).
    The plugin starts one when there is none.

==============================================================================
3. Install						*opencode-nvim-install*

With `vim.pack`: >lua

  vim.pack.add({ { src = "https://github.com/<you>/opencode-nvim" } })
  require("opencode-nvim").setup({})
<

For local development (points at the repository directory): >lua

  vim.opt.rtp:prepend("/home/toast/opencode-nvim")
  require("opencode-nvim").setup({})
<

Without calling `setup()` the plugin configures itself with the defaults on
`VimEnter`.

==============================================================================
4. Configuration					*opencode-nvim-config*

>lua
  require("opencode-nvim").setup({
    server = {
      command = "opencode2",   -- binary used to start the service
      autostart = true,        -- start the service when there is none
      url = nil,               -- force a server (e.g. "http://127.0.0.1:4094")
      password = nil,          -- force the password (default: service.json)
      state_dir = nil,         -- directory holding service.json
    },
    agent = "build",           -- default agent for new sessions
    model = nil,               -- nil = the last model used in the TUI
                               -- (e.g. { providerID = "opencode-go", id = "deepseek-v4.1-flash" })
    permissions = {            -- rules sent when the session is created
      edit = "ask",            -- (the V2 beta ignores this: see |opencode-nvim-approval|)
      shell = "ask",
    },
    approval = {
      review = "popup",        -- "popup" | "notify" | false
      agent = "opencode-nvim", -- agent whose rules ask for approval
      auto_detect = true,      -- use any agent that asks for approval
      permissions = {          -- rules written by :OpencodeApprovalAgent
        { action = "edit", resource = "*", effect = "ask" },
        { action = "shell", resource = "*", effect = "ask" },
      },
    },
    session = { history = 30, directory = nil },
    context = {
      auto = true,             -- a prompt started from a selection becomes @this
      max_bytes = 204800,      -- limit for attaching an unsaved buffer
      diff_max_lines = 300,
      diagnostics_max = 50,
    },
    reload = { enabled = true, set_autoread = true },
    ui = {
      panel = { width = 0.42, height = 0.32, max_width = 100, max_height = 22, border = "rounded", folds = true },
      input = { height = 4, border = "rounded" },
      diff = { width = 0.85, height = 0.6, border = "rounded" },
      focus_after_submit = "input",  -- "code" | "panel" | "input"
    },
    keymaps = {
      enabled = true,
      toggle = "<leader>tt",
      ask = "<leader>ta",
      ask_buffer = "<leader>tA",
      sessions = "<leader>ts",
      models = "<leader>tm",
      agents = "<leader>tg",
      diff = "<leader>td",
      interrupt = "<leader>tx",
      undo = "<leader>tu",
      events = "<leader>te",
    },
    log = { level = "warn", file = nil },
  })
<

5. Commands					*opencode-nvim-commands*

:Opencode					*:Opencode*
	Open/close the panel and focus the prompt.
:OpencodeAsk [text]				*:OpencodeAsk*
	Open the prompt pre-filled. From a selection it includes `@this`.
:OpencodeNew					*:OpencodeNew*
	Start a new session in the current directory.
:OpencodeAttach {id}				*:OpencodeAttach*
	Attach an existing session (including one open in the TUI).
:OpencodeSessions				*:OpencodeSessions*
	Pick a session of the current directory.
:OpencodeModels					*:OpencodeModels*
	Pick the session model.
:OpencodeAgents					*:OpencodeAgents*
	Pick the session agent.
:OpencodeInterrupt				*:OpencodeInterrupt*
	Interrupt the running turn.
:OpencodeUndo					*:OpencodeUndo*
	Undo the last turn (revert) and restore the files.
:OpencodeDiff					*:OpencodeDiff*
	Show the diff of the last turn (or of the working tree).
:OpencodeApproval				*:OpencodeApproval*
	Show which agents ask for approval and how the setup looks.
:OpencodeApprovalAgent				*:OpencodeApprovalAgent*
	Create the approval agent in the global OpenCode config.
:OpencodePermissions				*:OpencodePermissions*
	Decide permissions that were left for later (the turn stays paused).
:OpencodeEvents					*:OpencodeEvents*
	Inspect the events received from the server (useful for debugging).
:OpencodeHealth					*:OpencodeHealth*
	Check the connection, authentication and current session.
:OpencodeDoctor					*:OpencodeDoctor*
	Diagnose a turn that never answers: server, event stream, session state,
	last messages and the last events of the session.
:OpencodeLog [level]				*:OpencodeLog*
	Read/set the log level (debug, info, warn, error).

6. Keymaps					*opencode-nvim-keymaps*

  <leader>tt	toggle the panel
  <leader>ta	ask (visual: uses the selection as `@this`)
  <leader>tA	ask with `@buffer`
  <leader>ts	pick a session
  <leader>tm	pick a model
  <leader>tg	pick an agent
  <leader>td	diff of the last turn
  <leader>tx	interrupt
  <leader>tu	undo the last turn
  <leader>te	events

Inside the panel:
  i, a, <CR>	open the prompt
  q, <Esc>	close the panel
  <C-c>		interrupt
  gd		diff of the last turn
  r		resend the last prompt
  G		go to the end

While a turn is running the panel shows "▸ thinking…" (which gives way to the
content as soon as it arrives) and the title counts the elapsed time
("● 12s"). After 30s without any event a warning shows up in the panel naming
the last event of the session (use |:OpencodeDoctor| to dig further).

How the panel reads: >

  ❯ your message

  ▸ thinking (12 lines, zo opens)      reasoning, folded by default
  ▸ read /path/to/file ✓               tool call and its status
  the answer text                      plain text, no gutter
<
Reasoning is folded (zo opens one block, zR opens all) and guttered with "│ ",
so it stays distinguishable from the answer when expanded. Each new turn is
separated by a blank line, and after sending the prompt stays open for the next
message (see `ui.focus_after_submit`).

Inside the prompt:
  <CR>		send
  <C-j>		newline
  <C-x><C-o>	complete files and placeholders (@this, @buffer, ...)
  <Esc>		close without sending
  <C-c>		cancel the current turn

In the permission/diff popup:
  <CR>		allow once
  a		allow always (saves the rule)
  n		reject (with an optional message)
  <Esc>		decide later (the execution stays paused)

==============================================================================
7. Context					*opencode-nvim-context*

Inside the prompt, these markers are expanded before sending: >

  @this		current line, or the visual selection if the prompt came from it
  @buffer	current file (an unsaved buffer is sent as an attachment)
  @buffers	open files
  @diagnostics	diagnostics of the buffer/range
  @diff		git diff of the session directory

Example: `@this turn this into a local function`.

With `context.auto = true`, opening the prompt from a visual selection already
pre-fills `@this ` at the start of the text.

8. Approval and diff				*opencode-nvim-approval*

The plugin wants nothing written to disk without you seeing it, and does that in
two levels:

1. Pre-approval (the good one). When an agent whose rules ask for approval on
   `edit` exists, the turn pauses and the proposed diff shows up in Neovim; the
   file is written only after your `<CR>`. The plugin detects such an agent by
   itself. To create one, use `:OpencodeApprovalAgent`, which writes this to the
   global OpenCode config (`~/.config/opencode/opencode.json`): >

     {
       "agents": {
         "opencode-nvim": {
           "description": "OpenCode inside Neovim: asks for approval before editing",
           "mode": "primary",
           "permissions": [
             { "action": "edit", "resource": "*", "effect": "ask" },
             { "action": "shell", "resource": "*", "effect": "ask" }
           ]
         }
       }
     }
<
   Then run `opencode2 service restart`. Check the state with
   `:OpencodeApproval`.

2. Review after the turn (works with no config at all). When a turn that touched
   files finishes, the diff shows up in a popup: >

     <CR> keep       r undo the turn       <Esc> close
<
   `:OpencodeUndo` does the same from outside the popup.

In the permission popup: >

  <CR> allow once
  a    allow always (saves the rule for the project)
  n    reject (with an optional message)
  <Esc> decide later (the turn stays paused; see :OpencodePermissions)
<

The agent rules apply only to the plugin sessions; the TUI keeps its own
behaviour.

To tune it: >

  approval = { review = "notify" }   -- warn only, no popup
  approval = { review = false }      -- no review after the turn
  approval = { auto_detect = false, agent = "my-agent" }
<
Approved edits are written and open buffers reload on their own
(`reload.enabled`); Neovim's `undo` still works on the buffer.

NOTE: undoing a turn (restoring files) and the diff of a turn rely on OpenCode
snapshots, which use git. Outside a git repository the plugin falls back to the
working tree diff and warns that files were not restored.

	Table with the current state.

10. Events					*opencode-nvim-events*

Every server event fires a `User` autocommand: >

  OpencodeEvent:{type}   -- e.g. OpencodeEvent:session.text.delta
  OpencodeEvent         -- all of them
  OpencodeSessionChanged -- when the current session changes
<

Example: >

  vim.api.nvim_create_autocmd("User", {
    pattern = "OpencodeEvent:permission.asked",
    callback = function(args) vim.notify("permission asked") end,
  })
<

11. Troubleshooting			*opencode-nvim-troubleshooting*

  - `:checkhealth opencode-nvim` shows the service discovery state.
  - `:OpencodeHealth` runs a live check (connection + authentication).
  - `:OpencodeEvents` shows what is arriving from the server.
  - `:OpencodeApproval` shows whether an agent asks for approval.
  - `log = { level = "debug", file = "/tmp/opencode-nvim.log" }` records it all.
  - If edits do not reload, check `'autoread'` and `reload.enabled`.
  - If the service is not found, check `server.command` and that `opencode2` is
    in `PATH`.
  - If the diff/undo does not restore files, the directory is not a git
    repository (OpenCode snapshots use git).
  - If the panel shows a provider error ("Error from provider ..."), the problem
    is the account/service, not the plugin: the exact reason shows in the panel
    and `r` resends the last prompt. The opencode-go free tier is flaky and
    sometimes returns misleading messages (for example demanding "OpenCode 1.17.0
    or newer"); in practice the same model works again minutes later.
  - If a turn never answers, the panel warns after 30s and shows the last event
    received for that session; `:OpencodeDoctor` prints the whole state (server,
    stream, session, last messages, last events) and `:OpencodeEvents` shows the
    raw event log. `make probe-hang` reproduces it from a shell.
  - If *no* turn runs at all, check the model. The server default can be a
    blocked free tier model (on opencode-go, `opencode/union-alpha`). Without a
    configured `model` the plugin uses the last model from the TUI; to pin one,
    use `model = { providerID = "...", id = "..." }` or `<leader>tm`.

These V2 beta divergences are already handled by the plugin, but they help to
understand odd logs:

  - `permissions` in `POST /api/session` is ignored by the server; the real
    approval comes from the agent rules.
  - The permission reply expects the `reply` key (the OpenAPI says `decision`);
    the plugin sends `reply` and falls back to `decision` on a 400.
  - `GET /api/agent` is per location and only complete after the location is
    loaded; that is why the plugin calls `GET /api/location` first and re-queries.
  - `GET /api/session/{id}/diff` answers an empty 404 on this build; the plugin
    falls back to `GET /api/vcs/diff?mode=working`.
  - There is no `session.idle` in a normal turn: the end of the turn is
    `session.execution.succeeded` (or `failed`/`interrupted`).
